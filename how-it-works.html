How it works

Draw a starting pattern and press Start: every cell follows the same few rules, generation after generation.

Rules (B3/S23)

  1. Any live cell with fewer than two live neighbours dies (underpopulation).
  2. Any live cell with two or three live neighbours lives on to the next generation.
  3. Any live cell with more than three live neighbours dies (overpopulation).
  4. Any dead cell with exactly three live neighbours becomes a live cell (reproduction).

Neighbors are the up to eight cells touching a cell, diagonals included; cells outside the grid count as dead. In short, B3/S23 is Birth on 3 neighbors and Survival on 2 or 3. A live cell that doesn't survive dies.

Changing the rule

The Rule box takes the rule in B/S notation: B (birth), a slash, then S (survival), each followed by neighbor counts. The default is B3/S23.

  • B lists the neighbor counts that bring a dead cell to life. S lists the counts that keep a live cell alive; with any other count it dies. A change applies from the next generation.
  • Counts are the digits 0–8, written together: S23 means 2 or 3 neighbors. Each digit is its own count, so S12 is 1 or 2, never twelve. Their order doesn't matter, and B and S can be lower case.
  • An empty list means never: B2/S has no survivors, and B/S23 has no births.
  • The format is checked as you type: B first, then one slash, then S, and only the digits 0–8. If it doesn't fit, a message says what to fix and the previous rule keeps running.

Using the board

  • Draw: click or drag to bring cells to life or erase them, before or during a run. Reset returns to the grid you started from, Randomize fills a new one and Clear empties it.
  • Colors: alive is white and dead is black. Under Style, Highlight Just Born / Just Died cells (on by default) colors the cells that changed in the latest generation, in colors you can pick. Roundness rounds the cells' corners, from square (off) to round, and Speed sets generations per second.
  • Size: the grid is square, 3 × 3 to 300 × 300 (100 × 100 to start). The grid changes as you type the size and each new size starts a new random grid. Large grids take longer per generation, so the speed may not be reached, and above 200 × 200 the grid lines are hidden.
  • It stops when you press Stop, at the generation limit (250 to start, 1 to 1000), when all cells die, or when the grid is stable (a generation changes nothing). Repeating patterns such as the blinker keep running. Drawing a cell or changing the rules lets a stopped game run again.

Under the hood: how a generation is computed

All of the game's logic runs as Python inside your browser; the page only draws the grid and passes your input to it.

Every cell must be judged by the current generation, so changing one right away would corrupt its neighbors' counts. Instead of copying the grid, the game keeps one grid and gives each cell one of four states:

  • DEAD_CELL and LIVE_CELL: plain dead and alive.
  • WILL_BE_ALIVE: dead now, will be born. Counts as dead.
  • WILL_BE_DEAD: alive now, will die. Counts as alive.

A generation is two passes. Mark: count each cell's live neighbors and mark the cells that will change, so earlier decisions never change later counts. Settle: turn WILL_BE_ALIVE into LIVE_CELL and WILL_BE_DEAD into DEAD_CELL. The "will be" states only exist during the step, and the highlight and the rounded corners are drawn by the page, which finds the changed cells by comparing each generation with the one before.
